# 项目目标与验收清单

更新：2026-10-31。用户确认将已提出的交付缺口和新增功能全部列入目标。本清单表示后续工作范围，不表示已经实现或验证，也不表示自动创建了定时任务。

总目标：把“跟上了吗”做成可公开体验、可自行部署、能够支撑一场操作教学并持续复用的开源小项目。参与成本保持低，沉默不视为完成，回答不替参与者确认恢复。

用户约束：不使用 Docker，不把镜像或容器构建列入开发、部署、CI 或验收目标。部署直接使用 Python 虚拟环境与 Uvicorn。

## 当前基线

v0.3.0 已发布。已实现能力以 README 为准；已有 25 项本机测试及部分浏览器操作验证。持续负载、真实多设备弱网、原生部署验证、GitHub CI 和真实课堂效果尚未完成验证。此前短程 60 身份测试不能充当容量承诺。

## P0：完成公开交付与可靠性

- [ ] **G01 在线体验入口**：提供可访问的体验地址和双角色操作说明。演示环境与实际活动数据隔离，能限制滥用、重置演示数据；公开页面不暴露管理凭证和他人信息。部署依赖的域名、服务器与成本须明确。
- [ ] **G02 原生 Python 部署实证**：从干净 Python 虚拟环境安装依赖、启动、健康检查、二维码跨设备加入、SSE 同步；重启服务后持久数据保留。记录命令、环境和结果，失败必须留痕。
- [ ] **G03 升级及备份恢复演练**：用旧版本数据库副本升级，验证历史数据和权限；实际备份、恢复并复核数据。不用生产数据做破坏性演练。
- [x] **G04 CI 真正启用**：工作流进入 Actions 并实际通过后端测试、JavaScript 检查及原生服务启动检查。已通过连接的 GitHub 工具提交正式工作流；实际运行成功：[41088411889](https://github.com/jjy0230/gen-shang-le-ma/actions/runs/41088411889)，含 33 项测试、三份 JS 检查及原生健康检查。
- [ ] **G05 持续多人及故障测试**：10/30/60 身份、同出口 IP、至少 30 分钟持续连接与反馈，记录延迟和错误率；覆盖断网重连、重复点击、并发推进、权限撤销、浏览器刷新和手机锁屏恢复。对旧请求不覆盖新状态、失败不丢输入、跨步不串状态逐项验收。初步目标为指定环境下 30 身份状态同步 P95 ≤ 2 秒，未达成先如实记录。
- [ ] **G06 真实试用与复用验证**：先做约 10 人可用性试用，通过后再观察实际 20–30 人带练。记录加入耗时、主动反馈率、提醒次数、受阻被发现及自报恢复时间、讲解者实际查看行为与下一次复用意愿。需要真实组织者和参与者，不能拿脚本模拟替代；不主动联系或招募他人。原定门槛仅为待验证产品假设。

## P1：补齐软件安装带练的针对性

- [ ] **G07 课前环境自检**：正式开始前发布准备清单，收集下载、权限等准备情况；主持能区分未准备、受阻和已准备。复用检查点模型，不扫描设备、不自动假定准备完成。
- [ ] **G08 按环境分流帮助**：参与者可主动选择 Windows/macOS/Linux/其他；同一步可显示适用的说明和处理办法。未选择或更换环境不丢进度，主持能查看分布；不强制填写操作系统以外的信息。
- [ ] **G09 完成标准澄清**：增加轻量“我没看懂这一步要求”的入口，与操作失败分开统计；主持澄清后相关人可确认收到。提出疑问不自动判定步骤失败或完成。
- [ ] **G10 结构化求助补充**：先允许立即求助，再按卡点选填环境、错误代码和已尝试操作；不让长表单挡住受阻反馈，提示不要输入密码或敏感日志。暂无理由时仍能正常进入跟进列表。
- [ ] **G11 步骤更正及确认**：主持发布原步骤的更正版本，保留旧说明及发布时间；受影响者看到明确更正并可确认收到。更正不等同发布下一检查点，不静默重置原进度，历史复盘可解释版本变化。
- [ ] **G12 完成者的可选任务**：每步可配置一条复核或拓展任务，完成者可展开；与主线统计、完成标准分开，不强制提交，不增加等待者的负担。
- [ ] **G13 本步暂不参与与人数口径**：参与者可说明旁听、权限不足或暂时跳过；由主持明确决定是否排除本步分母。保留申请、决定和原因，不能自动提高完成率，不影响其他步骤与冻结的历史统计。
- [ ] **G14 主持发起一次进度确认**：温和突出当前反馈入口，单独统计本轮确认覆盖人数。已有完成者确认时不被重置；限制频率并允许关闭提示，不用连续弹窗催促参与者。

## 推进顺序与完成定义

先 G02–G05，准备 G01；再实现 G07、G08、G11，随后补 G09、G10、G12–G14。G06 的可用性观察尽早进行，完整效果验证在真实活动中完成。无法自行取得的人、服务权限、域名或付费资源应明确列出依赖，不把未获得的外部资源当作已授权或已可用。

功能目标至少包含实现、接口/权限回归、对应浏览器流程、文档与版本记录；涉及人数或历史的数据变更需验证旧库迁移。验收通过后再勾选，注明提交和验证证据。部署和效果目标分别按环境验证与真实试用证据完成，不能用功能测试代替。

## 暂缓方向（记录但不进入本轮实施）

AI 自动诊断/聚类、自动设备或安装状态监控、PPT/录音解析、完整课程管理、通用聊天、排行榜、计费和大规模多租户。它们之前被明确建议暂缓，本次“列为目标”不推翻这些边界；需要具体使用证据后再决定是否转为正式目标。
