# 真实设备与带练试用记录

本文件是待执行记录表，不是已取得的试用结果。不主动联系或招募参与者。

## G02：两台真实设备

组织者在电脑按 README 启动原生服务，设置 PUBLIC_URL 为手机可达的局域网地址，创建独立测试房间。手机扫码加入，报告进行中、卡住和完成，电脑核对状态；重启服务后重新打开双方页面并核对历史。不要把 localhost 分享给手机。

记录：日期、代码提交、电脑系统/Python、手机系统/浏览器、网络类型、扫码至加入秒数、各状态是否同步、重启后是否保留、失败现象。禁止记录凭证、完整内网地址或个人身份信息到公开仓库。

## G06：约 10 人首次试用

选择一次原本就会进行的软件安装或操作练习。提前写好 3–5 步与完成标准，保存主持凭证。先说明三个状态、求助与恢复确认；允许参与者继续采用原有求助方式，记录其真实选择。

观察者仅记过程，不替参与者点状态：加入耗时、每步开始/结束、首次受阻反馈/被主持注意时间、主持询问“好了没”次数、是否实际查看面板、处理办法发布和自报恢复时间、未反馈人数。记录时使用本次匿名编号，导出文件私下保管。

| 指标 | 计算方式 | 本次结果 |
| --- | --- | --- |
| 加入耗时 | 扫码到加入成功，记录中位数及范围 | 待执行 |
| 主动反馈率 | 提醒前反馈的人次 / 应反馈人次 | 待执行 |
| 受阻发现耗时 | 主持注意时间减首次受阻报告时间 | 待执行 |

结束后分别询问组织者“哪次决策用到了面板、何时仍依赖口头询问”，参与者“何时愿意点状态、何时忘记或不愿意”。先修复阻断使用的问题，再决定是否进入 20–30 人活动。不把满意度、模拟完成率或单次成功当成价值已证明。
